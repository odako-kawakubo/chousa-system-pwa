# v0.1.6.1C レビュー

## この版の目的

v0.1.6.1Cは、UI操作からの自動保存を始める前に、Firestoreへ「1レコードを正しい形で保存・削除・読込」する内部基盤を作る版。
あわせて、v0.1.6.1Bで確認された「その他1/2の空欄が勝手に『その他』へ変わる」不具合を修正する。

## 変更点

### 1. Firestore Repository新設

`src/js/firestore/firestore-repository.js`

3レコードの保存入口を統一した。

- `saveFinishRecord()`
- `saveMaterialRecord()`
- `savePhotoRecord()`
- `readProjectRecords()`

UIイベントとはまだ接続していない。後続版では個別にFirestore APIを呼ばず、このRepositoryを共通入口にする。

### 2. 3レコードserializer新設

`src/js/firestore/record-serializer.js`

Firestoreへ保存するフィールドだけをここで確定する。

#### finishRecord
保存：
`areaCode / roomPosition / floor / roomNo / roomName / position / part / materialId / systemMemo / updatedDevice / fieldEditedAt / updatedAt`

保存しない：
`finishId`（document ID） / `inputId` / `status` / `roomUid`

#### materialRecord
保存：
`status / materialId / name / part / usageLocation / level / note / analysisRequired / sampleCount / sampleLocation1〜3 / samplePart / sampleDone / sampleDate / sampleName / analysisResult / remarks / systemMemo / updatedDevice / fieldEditedAt / updatedAt`

保存しない：
`inputId / materialNo / baseName / suffixLetter / color / photoCount`

#### photoRecord
共通保存：
`photoId / photoType / fileName / isRepresentative / capturedDevice / capturedAt / isEdited / lastEditedDevice / lastEditedAt / deleted / systemMemo / boardPosition / boardSize / originalPath / completedPath / fieldEditedAt / updatedAt`

目視：
`areaCode / roomPosition / partSlot`

採取：
`materialId / samplingPlace / samplingBranch / sampleNo / part / shootingType`

保存しない：
`oneDrivePath / syncStatus / localOriginalStatus / localCompletedStatus`

### 3. finishRecord初期差分判定

正式初期値 `default-finish-data.js` と次の4項目だけ比較する。

- `roomNo`
- `roomName`
- `part`
- `materialId`

判定：

- 初期テンプレートにあり、4項目が初期値と同じ → Firestore差分docを削除
- 初期テンプレートにあり、差分あり → 1件保存
- 初期テンプレートに存在しない追加構造 → 空でも1件保存

ローカルStoreのfinishRecord自体は削除しない。

### 4. `fieldEditedAt` 基盤追加

`src/js/sync/field-edit-meta.js`

3レコードに `fieldEditedAt` を内部メタ情報として追加した。

役割：

- 項目ごとの編集確定時刻
- 将来のオンライン競合マージ
- オフライン復帰時のマージ
- 将来の端末間オフライン引継ぎ

UIには表示しない。

CではUI編集イベントへまだ接続しないため、既存UI操作が自動で `fieldEditedAt` を更新する処理は後続版で接続する。

### 5. `updatedAt` のFirestore側役割を固定

Repositoryが保存時に `serverTimestamp()` を注入する。

- `fieldEditedAt` = 実際の編集確定時刻
- `updatedAt` = Firestoreへ最後に反映された時刻

として混同しない。

### 6. 未送信キュー基盤

`src/js/sync/unsent-queue.js`

キー：

`projectId + recordType + recordId`

同じレコードは最新状態1件へ圧縮する。
保存失敗時はRepositoryから未送信へ入れ、保存成功時のみ該当未送信を削除する。

Cでは通常の「今回+過去最大3件」再送処理まではまだ接続しない。

### 7. 案件読込時のFirestore取得基盤

`readProjectRecords()` を追加。

#### 完全バックアップなし
3レコードとも、その案件のFirestore現在データを一式取得する。

#### 完全バックアップあり
- `materialRecords`：`updatedAt > backupAt`
- `photoRecords`：`updatedAt > backupAt`
- `finishRecords`：現在の差分docを一式取得

仕上表だけ一式取得する理由：
初期状態へ戻ったfinishRecordはFirestore差分docを物理削除する仕様のため、`updatedAt > backupAt`だけでは「バックアップ後に削除された」という事実を取得できない。

そのためfinishRecordは、`default-finish-data.js + 現在Firestoreに存在する差分doc一式`で現在状態を確定できるようにする。

### 8. 「その他1/2」空欄保持バグ修正

修正前は、その他1/2のpartが空欄でも、セル確定処理で自動的に「その他」へ変換していた。

修正後：

- 空欄をタップしただけ → 空欄
- 空欄のまま編集終了 → 空欄
- 部屋コピー元が空欄 → コピー先も空欄
- 建材を登録しても実部位未入力 → 空欄のまま
- 実際に部位を入力した場合だけ、その値をfinishRecord.partへ保存
- 建材の部位集計時だけ、建材あり＋part空欄を業務上「その他」として扱う

## Cではまだ行わないもの

- UI編集確定 → Firestore自動保存の本接続
- `fieldEditedAt`のUIイベント自動更新
- 複数端末 `onSnapshot()` リアルタイム同期
- 競合マージ本体
- 手動オフライン復帰処理
- オフライン端末間引継ぎ本体
- OneDrive完全バックアップ本体
- 画像アップロード本接続
