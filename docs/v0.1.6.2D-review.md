# v0.1.6.2D Review

## 目的
案件削除機能を追加し、端末容量の整理とテスト案件の掃除を可能にする。Cまでの仕上表全件保持・追加構造保存・写真Record保存復元は維持する。

## 変更内容

### 案件一覧の削除操作
- サンプル案件以外の案件カードに削除ボタンを追加。
- 本番案件は「端末から削除」。Firestoreは削除しない。
- `environment: test` のテスト案件は「完全削除」。端末内データと `testProjects/{projectId}` 配下を削除する。
- 開いている案件を削除した場合は公式サンプル案件へ戻す。

### 端末から削除する対象
- 端末内案件一覧 / 案件スナップショット
- 当該案件の未送信キュー
- 当該案件の看板設定
- 当該案件スナップショットに含まれるphotoIdのIndexedDB写真Blob / カメラ写真Record

### 未送信データ
- 未送信がある場合は件数を表示して警告する。
- ユーザーが削除を確定した場合のみ未送信キューも削除する。

### テスト案件のFirestore完全削除
- Firestore Web SDKは親Document削除だけではsubcollectionを削除しないため、
  `finishRecords` / `materialRecords` / `photoRecords` を先に分割batchで削除し、最後に `testProjects/{projectId}` を削除する。
- Firestore削除に失敗した場合は端末内案件を残し、再試行可能にする。

## 今回触っていないもの
- 仮案件採番ロジックの追加修正
- OneDrive案件一覧
- 本番案件のFirestore完全削除
- OneDrive写真ファイル削除

## 確認ポイント
1. 本番案件の削除ボタン → 端末一覧から消え、Firestoreには残る。
2. 削除した本番案件を別経路で再取得した場合、Firestoreから復元できる。
3. テスト案件の削除 → testProjects配下の3Record collectionと親Documentが消える。
4. 未送信あり → 警告が出る。
5. 開いている案件を削除 → サンプル案件へ安全に戻る。
6. 写真がある案件を端末削除 → 当該photoIdのIndexedDBキャッシュが消える。
