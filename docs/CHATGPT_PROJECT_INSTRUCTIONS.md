# ChatGPT「川久保」プロジェクト指示（貼り付け用）

システム開発（「しらべ」、単体カメラアプリ、関連システム）は、以下を常に守る。

1. **解析・相談と実装を分離する。** 「見て」「解析して」「不具合が出た」「どう思う」などは変更許可ではない。原因・影響範囲・修正方針を先に提示し、明確な実装指示までコード・GitHub・Firebaseを変更しない。
2. **継ぎ足し修正は原則禁止。** 対象モジュール・処理の入口・依存関係・保存同期を解析して適切に書き換え、不要な旧関数・イベント・CSS・import・重複処理を整理する。既存データと互換性が必要なコードは保持する。
3. **通常の8ステップ：** 解析 → 修正方針の合意 → 実装 → テスト・レビュー公開 → 実機確認と修正 → 確定版作成 → main反映・本番公開 → 完了報告。
4. **権限の段階を厳守。** 実装、レビュー公開、main反映、本番公開は別。合意済み範囲内のレビュー修正は同じブランチで繰り返せるが、新仕様や別機能は再確認する。「うん」「OK」「進めよう」は対象と作業内容が明確でない限り承認とみなさない。
5. **ブランチ：** mainは確定版、通常開発はworkを1本継続利用。並行開発が必要な場合だけfeature/fixを作る。確定後workを最新mainと整合させ、古いブランチは調査・承認後に段階的整理する。確定版はタグで保管する。英字枝番は固定ルールにしない。
6. **レビューURLを固定。** 通常開発の従来URLは https://odako-chousa-system-pwa--v0163a-djc70l4o.web.app/app.html 。review-photo-pdfは一時利用であり標準ではない。公開前に設定・期限・競合を確認し、URLや公開先を無断変更しない。
7. **main pushは現行構成で本番自動デプロイにつながる。** mainへの更新は本番影響を持つものとして承認を確認する。ワークフローやFirebase設定も勝手に修正しない。
8. **全体整理・仕様書：** コード全体の整理はChatGPTとClaudeの独立レビューを照合して計画し、承認後に修正する。仕様書は機能確定時や全体整理時にまとめて更新する。既存挙動・保存・同期・オフラインを守る。
9. **報告：** 変更したファイル、不要コードの整理、テスト、GitHubコミット、公開先、未確認事項を区別する。未実施の動作確認を成功と主張しない。

正式な詳細規定はGitHub `chousa-system-pwa/docs/DEVELOPMENT_RULES.md`。このプロジェクト指示との不一致があればユーザーへ確認する。

## スレッド上限に備えた引き継ぎ（2026-11-11合意）

- 新規スレッドではGitHub `docs/CURRENT_HANDOFF.md` と `docs/TECHNICAL_OPERATIONS.md` を、開発ルールとともに先に読む。必ず現行ブランチ・Actions・コードと照合する。
- 開発・テスト・公開・レビューなど承認済み作業の区切りで、`CURRENT_HANDOFF.md` の進捗／失敗／未実施／次作業を更新し、前回の古い説明を整理する。スレッドが長くなってからまとめようとしない。
- 技術的な成功・失敗から確定した運用知見は `TECHNICAL_OPERATIONS.md` へ更新する。ただし推測と確認済み事項を区別する。
- これらは**GitHubファイルを作業時に更新する運用**であり、ChatGPTが会話終了後に自律的・定期的に更新する仕組みではない。更新自体の権限も `DEVELOPMENT_RULES.md` に従う。
